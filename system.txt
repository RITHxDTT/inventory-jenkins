# Project: Inventory Management System

Build a complete, clean, maintainable, and functional **Inventory Management System** using **Python, Django, PostgreSQL, Django Templates, Bootstrap 5, and Tabler UI**.

The application must be a server-rendered Django web application. Do not use React, Vue, Angular, or another SPA framework.

The system must support authentication, authorization, user management, product management, category management, supplier management, stock management, transaction history, reports, audit logs, search/filtering, and a responsive dashboard.

# 13. Stock Management

Stock management is a critical part of this project.

Do NOT treat stock changes as simple uncontrolled edits to the product quantity.

Create controlled Stock In and Stock Out operations.

## Stock In

Required fields:

# 14. Stock Out

Required fields:

* Product
* Quantity
* Reason
* Reference number
* Date
* Note

Automatically record:

* User
* Quantity before
* Quantity changed
* Quantity after
* Timestamp

Example:

Current stock = 30

Stock Out = 5

New stock = 25

IMPORTANT:

Never allow Stock Out quantity to exceed available stock.

Example:

Available stock = 5

User requests Stock Out = 10

Reject the transaction and display a clear validation error.

Stock must never become negative.

---

# 15. Transaction Safety

Stock changes and transaction creation must be atomic.

Use Django database transactions such as:

`transaction.atomic()`

When updating stock, handle concurrency safely.

Where appropriate, use database locking such as:

`select_for_update()`

The following operations must behave as one transaction:

1. Read/lock product
2. Validate stock
3. Calculate new quantity
4. Update product quantity
5. Create StockTransaction
6. Commit

If any part fails, the entire operation should roll back.

Do not create a transaction record if the stock update failed.

# 34. Important Business Rule

Product quantity must NOT be changed casually from the normal product edit form after the product is created.

After initial setup, inventory quantity changes should happen through controlled inventory operations such as:

* Stock In
* Stock Out
* Controlled adjustment if implemented

This is necessary so transaction history remains consistent.

For example, do NOT allow a staff member to edit:

Quantity: 100

directly into:

Quantity: 500

without creating a corresponding inventory transaction.

---

# 35. Data Integrity

The following relationship must always remain true:

Product.current_quantity = result of valid inventory movements

For every stock transaction:

quantity_after must correctly correspond to quantity_before and transaction quantity.

For IN:

quantity_after = quantity_before + quantity

For OUT:

quantity_after = quantity_before - quantity

Never allow:

quantity_after < 0
